# Refactor Log

## 2025-11-09 — Публичные фасады для auth, auth-button, movie-search, entities

### Что сделано

-   Добавлены входные точки `src/features/auth/index.ts`, `src/features/auth-button/index.ts`, `src/features/movie-search/index.ts`, `src/features/modal/index.ts`.
-   Созданы фасады для сущностей `movie` и `user` (`src/entities/movie/index.ts`, `src/entities/user/index.ts`), экспортирующие типы и UI-компоненты.
-   Переведены импорты в страницах, виджетах и shared-хуках на новые публичные API.
-   Внутренние файлы фич используют относительные импорты (`../model/...`), чтобы не образовывать циклы.

### Зачем

-   Слои приложения теперь не «протекают» наружу своими внутренностями: контролируем, что доступно другим частям.
-   Проще рефакторить структуру — переименование или перемещение файлов достаточно отражать в фасаде.
-   Интеграционные точки (`store`, `widgets`, `pages`) читают зависимости по бизнес-смыслу, а не по физической структуре директорий.

### Что даёт

-   Импорт любого auth-хука теперь выглядит единообразно: `import { useCurrentUser } from "@/features/auth";`.
-   Визуальные компоненты сущностей (`MovieCard`, `MovieDetails`, `MovieCardSkeleton`) подключаются из одного места.
-   Уменьшился риск ошибок в Server Components: фасады можно расширить `index.client.ts`, если появятся чисто клиентские части.
